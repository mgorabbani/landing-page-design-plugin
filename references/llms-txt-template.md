# llms.txt — template & generator spec

Every site the skill generates ships with an `llms.txt` at the project root. The format is a simple Markdown-with-conventions file that helps AI crawlers understand the site quickly.

## Spec reference

- Format: Markdown
- Path: `/llms.txt` (served at the site root)
- Optional: `/llms-full.txt` with expanded content when the site has substantial documentation

## Base template

Fill in every bracketed placeholder from what was actually built. Do not emit placeholders to disk.

```markdown
# [Site / Brand Name]

> [One-sentence description — what this site is for.]

[Optional 2–3 sentence expansion: who this is for, the primary value, any critical disambiguation ("we are X, not Y").]

## Primary actions

- [Critical CTA label]: [absolute URL or relative path]
- [Secondary CTA label, if any]: [URL]

## Key pages

- [Homepage]: /
- [Page name]: /path
- [Page name]: /path

## [Domain-specific section]

[One of the domain-specific sections below.]

## Contact

- Email: [email]
- Phone: [phone, if applicable]
- Address: [address, if physical]

## Meta

- Last updated: [YYYY-MM-DD]
- Generated by: landing-page-design skill
```

## Generator rules

When writing `llms.txt`, the agent must:

1. Use absolute URLs only if the user provided a production domain; otherwise root-relative paths.
2. Include **every** primary CTA that appears on the site (usually 1, sometimes 2).
3. List every top-level page route that exists after the build.
4. Pick the matching domain section above; drop anything that doesn't apply.
5. Date the file with today's date in `YYYY-MM-DD` form.
6. Keep the whole file under ~2000 words — this is a signpost for crawlers, not the site's full content.
7. Write it to `public/llms.txt` (Next.js / Vite / etc.) so it serves at `/llms.txt`. If the framework doesn't have a `public/` folder, write to wherever static assets live (`static/` for SvelteKit / Remix, `assets/` for Astro's public output).

## Optional `llms-full.txt`

If the site has substantial documentation, blog, or policy content, also emit `llms-full.txt` with the expanded Markdown of those pages concatenated (headings preserved). Only generate when the site actually has that content — don't pad.
